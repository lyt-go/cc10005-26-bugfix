# 清洗规则与去重引擎指纹绑定：缺陷修复说明

## 1. 背景与缺陷

| 缺陷 | 复现路径 | 根因 |
| --- | --- | --- |
| 旧指纹误判 | DATA-0001 停用后，DEDU-0001 仍用旧指纹把新记录判重 | `dataclean` 与 `dedupengine` 两张表无任何绑定，规则停用没有任何机制通知去重侧 |
| 停用引擎复活 | 已停用引擎直接点「启用引擎」恢复旧字段组 | `run_action` 只校验动作名，从不校验当前状态，状态机形同虚设 |
| 孤儿指纹 / 不一致 | 重复停用、并发规则变更 | store 无锁，跨表写入非原子；动作可重复执行 |
| 动作入口对不上 | 前端动作按钮全量渲染、统计卡恒为 0 | 前端不按状态过滤动作；stats 硬编码；动作请求体与后端契约不符（`{action}` vs `{values:{action}}`） |

## 3. 处理结构

- **指纹登记表 `dedupfingerprint`**（内部表，不进概览/导航）：
  `指纹编号 = FP-<引擎编号>-v<字段组版本>`，字段含 `绑定规则编号`、`滑动窗口天`、
  `指纹状态(生效中/已退出)`、`创建时间`、`退出时间`、`退出原因`。
  指纹只改状态不删记录 —— 历史去重判定保留，旧记录不重新判定。
- **绑定关系**：`dedupengine.绑定清洗规则 -> dataclean.规则编号`（一对多，
  一条规则可被多个引擎引用）；`字段组版本` 记录引擎当前版本。

## 4. 状态机流程图

### 清洗规则（dataclean）

```
                 提交规则验证          启用规则           废弃规则
  ┌──────┐  ───────────────► ┌──────────┐  ──────────► ┌────────┐  ──────────► ┌────────┐
  │ 草稿 │                   │ 规则验证中 │              │ 已启用 │              │ 已废弃 │
  └──────┘                   └──────────┘              └────────┘              └────────┘
                                                                │                    ▲
                                                                ▼ 废弃规则(锁内)      │ 终态
                                                   引用本规则的生效指纹 ──► 已退出     │
                                                   响应列出受影响引擎+滑动窗口          │
                                                   重复废弃 ──► 拒绝，无副作用 ─────────┘
```

### 去重引擎（dedupengine）

```
              提交引擎评估         启用引擎            停用引擎
  ┌──────┐ ───────────────► ┌──────────┐ ──────────► ┌────────┐ ──────────► ┌────────┐
  │ 草稿 │                  │ 引擎评估中│             │ 已启用 │             │ 已停用 │
  └──────┘                  └──────────┘             └────────┘             └────────┘
                                  ▲                        │                     │
                                  │                        ▼ 停用(锁内)           │
                                  │              本引擎生效指纹 ──► 已退出         │
                                  │              (已被规则退出的跳过，幂等)        │
                                  │                                                │
                                  └──────────── 提交引擎评估 ◄─────────────────────┘
  启用引擎前置校验（锁内，顺序执行）：
    1. 有指纹履历 ⇒ 必须提交更大的「字段组版本」，否则拒绝(extra.need_version=true)
    2. 绑定清洗规则必须「已启用」，否则拒绝（防孤儿指纹）；可在请求里换绑
    3. 通过 ⇒ 登记新指纹 FP-<引擎>-v<新版本>，旧指纹保持已退出不复活
```

## 5. 改动位置清单

| 文件 | 改动 |
| --- | --- |
| `backend/app/store.py` | 增加 `threading.RLock` 与 `locked()` 原子区；`dedupfingerprint` 标记为内部表，不进概览 |
| `backend/app/seed.py` | dedupengine 增加 `绑定清洗规则`、`字段组版本`；新增 `dedupfingerprint` 种子（FP-DEDU-0003-v1 生效中） |
| `backend/app/services/dataclean.py` | 单向状态机；废弃规则在锁内级联退出引用指纹，返回受影响引擎+滑动窗口；详情附 `引用指纹` |
| `backend/app/services/dedupengine.py` | 单向状态机；启用时版本校验(need_version)+绑定规则校验+锁内登记指纹；停用时幂等退出指纹；详情附 `指纹列表` |
| `backend/app/routers/dataclean.py` `dedupengine.py` | 动作接口透传 `values` 与 `extra` |
| `backend/app/schemas.py` | `ActionResult` 增加 `extra` 字段 |
| `frontend/src/views/dataclean/index.tsx` | 动作按状态渲染；stats 用列表数据计算；修复动作请求体契约；详情展开显示引用指纹；操作反馈替代残留错误 |
| `frontend/src/views/dedupengine/index.tsx` | 同上 + need_version 时弹窗补录版本号；列表增加绑定规则/版本列；详情显示指纹履历 |
| `frontend/src/styles/global.css` | 新增 `ok-text`、`muted`、`detail-panel` 样式 |

## 6. 验证结论（DATA-0001 / DATA-0003 / DEDU-0001 / DEDU-0003）

1. **旧指纹失效**：DATA-0001 废弃 ⇒ FP-DEDU-0001-v1 退出新接入，响应列出
   DEDU-0001 与滑动窗口；指纹记录保留（历史判定不变）。
2. **重复提交**：重复废弃 DATA-0001、重复停用 DEDU-0001 均被状态机拒绝，无副作用。
3. **版本恢复**：已停用 DEDU-0001 不能直接启用；重新评估后缺版本/旧版本被拒；
   绑定规则已废弃被拒（防孤儿）；换绑已启用规则 + v2 启用成功，生成 FP-DEDU-0001-v2。
4. **并发**：10 线程并发废弃 DATA-0003 / 停用 DEDU-0003，均仅 1 次生效，
   指纹台账无重复、无孤儿。
